# REG.RU: автоматическая публикация лендинга «Бани Вятки»

## Архитектура

Исходный код и PR: GitHub, ветка `main`.
Сборка и публикация: `.github/workflows/build-site-archive.yml` (GitHub Actions).
Публичные файлы: REG.RU, `/var/www/u3717330/data/www/banivyatki.ru/`.
Приватный PHP: REG.RU, `/var/www/u3717330/data/www/private/`; **не публикуется GitHub Actions**.
Домен и DNS на время восстановления: banivyatki.ru, DNS Beget; переключать только после приёмки.

В `dist/` должны находиться `index.html`, `.htaccess`, `api/lead.php`,
`privacy/index.html`, `assets/`, `photos/` и прочие публичные файлы.
Нельзя использовать ZIP исходников репозитория вместо `dist/`.
Ключ Яндекс Карт берётся из существующего GitHub Actions secret `VITE_YMAPS_KEY`.

## Первый запуск без отдельного FTP-пользователя

1. REG.RU → услуга хостинга «Хост-А» → **Доступы** → получить действительные
   сервер/логин/пароль *основного* FTP-аккаунта. Не использовать `banivyatki.ru`
   как FTP-хост, пока DNS указывает на Beget. Не отправлять пароль или скриншот
   с секретами в чат или GitHub.
2. Определить **FTP-видимый** путь к директории сайта: он может отличаться от
   абсолютного пути Linux `/var/www/u3717330/data/www/banivyatki.ru/`.
   Проверить его при подключении через защищённый FTP-клиент или документацию
   конкретного хостинга; не угадывать. Значение должно оканчиваться на
   `/banivyatki.ru/`, например `./www/banivyatki.ru/` **только если этот путь
   реально подтверждён**. Папка `private` должна быть соседней, а не внутри
   каталога сайта.
3. GitHub → репозиторий → **Settings → Secrets and variables → Actions**.
   В **Secrets** добавить `REG_FTP_SERVER`, `REG_FTP_USERNAME`,
   `REG_FTP_PASSWORD`. Не использовать старые `FTP_SERVER` и т. п. Beget.
4. В **Variables** создать `REG_FTP_DIR` (проверенный путь) и
   `REG_DEPLOY_MODE` со значением `dry-run`.
5. Объединить подготовленный PR с `main` после review. Действующий
   Beget workflow больше не выполняется на push; REG.RU workflow соберёт
   сайт и запустит тестовую синхронизацию **без записи файлов**.
   Смотреть вывод Actions, подтвердить адрес сервера и корректный каталог.
6. После успешного dry-run и одобрения владельца изменить
   `REG_DEPLOY_MODE` на `live` и вручную запустить workflow через
   Actions → **Build and deploy site to REG.RU** → Run workflow (`main`).
   После успешного deploy проверить по файловому менеджеру, что
   `index.html`, `.htaccess`, `api/`, `assets/`, `photos/` и `privacy/`
   находятся непосредственно в `www/banivyatki.ru/`.
   Стандартный `index.html` REG.RU будет заменён; `private/` не затрагивается.
7. После подтверждения приёмки `REG_DEPLOY_MODE=live` обеспечивает
   автоматическую публикацию при каждом последующем push в `main`.

Если сервер не поддерживает **FTPS с проверкой TLS-сертификата**, не переходить
на обычный незашифрованный FTP. Следует подготовить альтернативный SFTP/SSH
workflow, прежде чем включать live.

## Защита

- Основной FTP-логин проще в настройке, но его права шире, чем у отдельного
  пользователя. Даже если `server-dir` указывает только на сайт, сам секрет
  может дать доступ к другим папкам аккаунта. По возможности в дальнейшем
  заменить его ограниченным пользователем или ключом.
- `REG_DEPLOY_MODE` по умолчанию отсутствует/выключен: без явного
  `dry-run` или `live` GitHub только собирает архив, но не подключается
  к REG.RU. Запуски PR никогда не публикуют сайт.
- FTPS: порт 21, `security: strict`; полная очистка директории отключена.
- Не публиковать/сохранять в `dist/` секреты `private/config.php`, webhook,
  `queue/`, `retry.php`. Сборка проверяет их отсутствие.
- Основной `api/lead.php` использует
  `dirname(__DIR__,2) . '/private/lib.php'`, что соответствует соседним
  `www/banivyatki.ru/` и `www/private/`.

## Приёмка перед переключением DNS

- Проверить права доступа к `private/config.php` (600), наличие `lib.php`
  и `retry.php`, синтаксис PHP и расширения.
- Проверить содержимое конфигурации без вывода секрета: актуальность REST-кода
  стадии, ID справочников и вебхука. Успех `php -l` сам по себе не доказывает
  работу с CRM.
- Проверить по новому IP правильный сайт/HTTPS и реальные формы с Битрикс24;
  учесть возможные различия веб-/CLI-PHP, настройки cron и сертификата.
- Проверить Яндекс.Метрику, Callibri и ключ Яндекс Карт.
- Только после этого поменять **A-записи для banivyatki.ru и www** у DNS-
  провайдера; сохранить MX/TXT/SPF и остальные записи почты. Не менять NS
  без отдельного плана переноса всей DNS-зоны.
- Настроить CRON для `/opt/php/8.5/bin/php ~/www/private/retry.php`,
  когда интеграция и очередь будут проверены.
