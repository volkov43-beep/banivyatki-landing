# CLAUDE.md — памятка по проекту «Бани Вятки»

Лендинг компании «Бани Вятки» (Киров): мобильная баня «Подкова» — готовая
конструкция, которую привозят и ставят на участке. Покупатель делегирует:
страница говорит на языке «что вы не будете делать», а не «какая у нас баня».
Каждый блок заканчивается числом или проверяемым фактом.

Репозиторий публичный: https://github.com/volkov43-beep/banivyatki-landing

## Стек и сборка

- Vite 7 + React 19 + Tailwind CSS 3. JavaScript, без TypeScript.
- `npm install`, `npm run dev` (локально), `npm run build` (в `dist/`),
  `npm run preview` (просмотр сборки).
- Две страницы Vite: `index.html` (лендинг) и `privacy/index.html` (`/privacy/`).
  Входы заданы в `vite.config.js`.
- Пути к файлам из `public/` в коде — через `import.meta.env.BASE_URL`,
  в HTML — через `%BASE_URL%`. Иначе на GitHub Pages ссылки сломаются.

### Деплой на GitHub Pages

Workflow `.github/workflows/deploy-pages.yml`: при пуше в `main` (или вручную
через «Run workflow») собирает сайт с `--base=/banivyatki-landing/` и публикует
`dist/` через `actions/deploy-pages`. Адрес: https://volkov43-beep.github.io/banivyatki-landing/
В Settings → Pages источник должен быть «GitHub Actions». Для приватного
репозитория Pages доступен только на платных планах GitHub.

Рабочий процесс: ветка от `main`, коммиты, push, pull request. После мержа
ветку пересоздавать от `main`, а не стекать поверх влитой истории.

## Дизайн-система

Токены объявлены в `src/styles/tokens.css` и подключены в Tailwind через
`theme.extend` (`tailwind.config.js`). Использовать классы Tailwind
(`bg-ink`, `text-surface`, `text-heading` …), не хардкодить значения.

### Палитра

| Токен | Значение | Где |
| --- | --- | --- |
| `ink` | #1A1512 | тёмный фон, крупный текст на светлом |
| `forest` | #10231D | тёмно-зелёный из логотипа: только фон тёмных карточек и блоков |
| `surface` | #F4EADF | светлый фон, текст на тёмном |
| `surface-2` | #ECE1D3 | панель на фоне surface (форма калькулятора) |
| `accent` | #C98A2E | акценты, размерные линии, кнопки, цена |
| `muted` | #6E7A6A | границы и второстепенный текст на светлом (3,8:1 — AA для мелкого текста не проходит, известно) |
| `alert` | #8C3F1D | проблемные места на схемах, ошибки на светлом |
| `muted-on-dark` | #9AA396 | второстепенный текст и линии на фоне ink (6,9:1) |
| `alert-on-dark` | #D9663A | проблемные места на тёмном фоне (5,1:1) |

На тёмном фоне использовать только `*-on-dark`. Не использовать: зелёный
как доминанту, терракоту около #D97757, градиентные заливки, тени под карточками.

Правила для `forest`:
- Только **фон** тёмных карточек и блоков. Не для текста и не для заголовков
  на бежевом: там он почти не отличается от чёрного.
- На `forest` работают те же цвета, что на `ink`: светлый текст — `surface`,
  второстепенный — `muted-on-dark`, акцент и кнопки — `accent`. Контраст
  проверен: 13,8 / 6,3 / 5,6.
- Где он есть: карточка вопроса в FAQ. Позже — финальная форма и подвал, при их
  сборке. Hero, калькулятор и сравнение остаются на `ink`.
- Поля на `forest`: прозрачный фон, рамка `rgba(244,234,223,0.28)`, текст
  `surface`, плейсхолдер `muted-on-dark`; `Segmented` со `scheme="dark"`.

### Типографика

Гарнитура Onest (Google Fonts), веса 400 и 700, кириллица.

| Класс | Размер | Вес | Интерлиньяж |
| --- | --- | --- | --- |
| `text-heading` | clamp(32px, 5vw, 56px) | 700 | 1.05 |
| `text-lead` | clamp(18px, 2.2vw, 24px) | 400 | 1.45 |
| `text-title` | 20px | 700 | 1.2 |
| `text-body` | 17px | 400 | 1.5 |
| `text-label` | 14px | 400 | 1.2 |

Длина строки не больше 70 символов (`max-w-measure`). Заголовок первого
экрана — своя формула `clamp(40px, 3.38vw, 49px)`, чтобы укладываться в три строки.
Запрещено: разрядка и капс, выделение слова в заголовке цветом или курсивом,
стрелки в тексте кнопок, моноширинный шрифт для подписей.

### Сетка и брейкпоинт

- Контейнер `max-w-container` (1200 px), отступы `px-gutter` 24 / `md:px-gutter-lg` 48.
- Секции `py-section-y` 64 / `md:py-section-y-lg` 96.
- Брейкпоинт раскладки — **1024 px** (`lg:`): до 1023 мобильная раскладка,
  от 1024 компьютерная. Шапка и первый экран, калькулятор, экран «Что внутри»
  переключаются именно на `lg`.

### Схемы

Все схемы — инлайновый SVG в чертёжной манере: контуры без заливки,
размерные и выносные линии `accent`, подписи через общий модуль
`components/diagrams/Diagram.jsx` (схемы `dark` / `light`, режим `scale`,
при котором подписи держат заданный размер в px на любом масштабе).

## Порядок блоков на странице (все сделаны)

1. `Header` — логотип 64/48 px со ссылкой на начало, телефон (на телефоне плашка).
2. `SectionHero` — картинка `<picture>` (мобильный файл до 1023, горизонтальный
   от 1024), заголовок «Баня-Подкова: / шире бочки, с ровным полом, под ключ»,
   подзаголовок, цена `от MIN_PRICE`, одна кнопка на `#calculator`, факты доверия.
3. `SectionComparison` — тёмный экран: главная схема бочка/Подкова,
   подпись, четыре блока преимуществ (от 1024 px сетка 2 × 2 по верхнему краю).
   Главная схема — готовый чертёж `diagram-sravnenie.webp` (1600 × 800, 2:1,
   прозрачный фон, WebP качества 85, меньше 250 КБ) в одном SVG с viewBox
   в размер картинки; размеры и подписи поверх: 2000 мм, «высота над головой»,
   «трапик 40 см» (alert-on-dark), 2400 мм, 2300 мм, «пол 2000 мм» (accent),
   названия «Баня-бочка» и «Баня-Подкова» 18 px жирные surface на одной базовой линии. Опорные точки
   в `G` измерены по пикселям файла (427 единиц = 2000 мм), не на глаз.
   До 600 px — та же картинка двумя SVG друг под другом с окнами viewBox
   одинаковой ширины 820, чтобы люди остались одного роста. Картинка
   грузится лениво (href по IntersectionObserver).
   Порядок в блоке: заголовок → схема → текст → фото → подпись. Фото есть в
   трёх: парная 1:1 (`shirina-parnaya.webp`), обвязка 4:3 (`obvyazka.webp`),
   проливной пол — пара 4:3 (`prolivnoy-pol-sverhu.webp` и `-razrez.webp`,
   до 600 px друг под другом, подписи 13 px, сноска про комплектации под парой).
   «Дуга стен» без фото. Фото со скруглением 6 px, без рамок и теней.
   В «Без стяжек» и «Дуге стен» вместо микро-схем — готовые чертежи
   `diagram-obvyazka.webp` (1440 × 850) и `diagram-duga.webp` (1440 × 1362):
   WebP с прозрачностью, качество 85, каждый меньше 200 КБ, без скругления.
   Подписи ставит `LabeledDrawing`: один SVG с viewBox в размер картинки,
   внутри `<image>`, поверх текст 14 px (`dg-label`, через `--s`) цветом
   muted-on-dark и выноски 1.5 px accent с точкой; до 600 px вместо текста —
   золотые номера в кружках и список под картинкой. Картинка грузится лениво
   (href ставится по IntersectionObserver). У SVG `role="img"` и `aria-label`.
4. `SectionCalculator` (`#calculator`) — вкладки «Себе / Для бизнеса», сезон,
   три карточки, панель формы, полоска на телефоне.
5. `SectionInside` — светлый экран: пять блоков (вентиляция, утепление, печь,

7. `SectionReviews` (`#reviews`) — светлый экран: заголовок «Что говорят владельцы

   карточка `FaqQuestionForm` на фоне `forest`: «Не нашли ответ?», подзаголовок
   с обещанием по московскому времени, поля «Ваш вопрос» (обязательное), «Имя»,

9. `Footer` — оператор, телефон, почта, ссылка на `/privacy/`.

Ещё не сделаны: галерея работ, шоурум (`#showroom`), подключение

## Калькулятор

- Данные — только в `src/data/calculator.js`: сезоны, карточки (id, название,
  размер, планировка, фото, цена, состав, доставка), примечания, цитата,
  тексты «Для бизнеса», телефон. `MIN_PRICE` считается оттуда и показывается
  на первом экране — цены на странице не могут разойтись.
- Планировки (`LAYOUTS`) в одном масштабе: viewBox рассчитан на 6 м,
  длина прямоугольника пропорциональна длине бани. Без метражей комнат.
- Карточки — радиогруппа (стрелки, пробел, фокус, `aria-checked`).
- После выбора: пауза 250 мс, прокрутка к панели формы (верх на 96 px),
  рамка панели 1,2 с `accent`; на компьютере фокус в телефон, на телефоне нет.
  Если форма видна — только строка-итог. На телефоне, пока форма за экраном,
  снизу закреплена полоска с итогом и кнопкой.

  warranty / company — на странице не показывается), `q`, `text` (абзацы через
  пустую строку, ссылки `[текст](#id)`), `list`, `after`. `plainAnswer()` даёт
  текст без разметки для JSON-LD.
- Перед публикацией подтвердить (пометки ❓ в черновике): № 3 — про наценку
  за безнал не пишем; № 4 — до какого момента можно менять комплектацию;
  № 13 — вентзазор во всех круглогодичных комплектациях, проливной пол только
  в круглогодичных. № 9 подтверждён: «сваи или блоки», сумму не пишем.
- Сознательно не включены: печь (марка, мощность), порода дерева по
  комплектациям, расстояния до забора и дома, возврат аванса (нужно решение
  Ильи — тогда вопрос № 19), сравнение с бочкой (есть блок).
- В № 17 ссылку на блок «Три способа посмотреть баню» добавить, когда он появится.

## Фотографии

- Только WebP, качество 80, в `public/photos/`. Ширина: карточки калькулятора
  800 px, фото в блоках 1200 px, первый экран 1920 / 1280 / мобильная 1080.
- Оригиналы (JPG с фотосессии) в репозиторий не коммитить.
- Конвертация через sharp (в проекте не установлен, ставить в отдельной папке):
  `sharp(src).resize({ width }).webp({ quality: 80 })`.
- `PhotoSlot`: `src` относительно `public/`, `aspect`, `objectPosition`,
  `scheme="light"` на светлом фоне, `className` для картинки (`rounded-md`),
  `captionClass` для подписи (по умолчанию `text-label`); пустой `src` —
  полоса-заглушка «фото».
- Логотип: `logo-128.webp`, `logo-256.webp` (обрезан круглой маской, без каймы),
  из него же favicon и apple-touch-icon.

## Правила, которые нельзя нарушать

- Минимальная цена калькулятора = цена на первом экране: **293 000 ₽**.
  Первый экран берёт `MIN_PRICE` из `src/data/calculator.js`, руками не писать.
- В карточках только «от», без диапазонов «от–до».
- «Подкова» с большой буквы, когда это название продукта («Баня-Подкова»,
  «У Подковы пол прямой»). Строчная — только для формы («формы подкова»).
- В готовых банях 4–6 м (тёплый сезон) не упоминать двойной проливной пол
  и вентиляцию «живая баня» — их там нет.
- Не упоминать басту, наценку за оплату картой, окна 300×300, мощность
  подключения (киловатты и сечения для участка).
- Без анимаций появления по скроллу, таймеров, всплывающих окон, бейджей
  «Акция»/«Хит», иконок в карточках и блоках преимуществ.
- Одна кнопка на первом экране. Никаких вторых кнопок, видеозвонков, форм там.
- Банковские реквизиты на сайт не выводить (в политике только ИНН/ОГРН/адрес).
- **Формы пока никуда не отправляют заявки. Рекламу не запускать до
  подключения Битрикс24.**
- Никаких секретов в репозитории — он публичный. Вебхуки, токены, пароли
  только на сервере.
- Дизайн-токены, гарнитуру и сетку не менять без отдельного задания.
- Пол Подковы 2000 мм, наружная ширина 2400, высота 2300 — цифры публичные,
  их повторяет менеджер.

## Что дальше

**Интеграция с Битрикс24** через PHP-обработчик на хостинге Beget:

- На сервере лежит `lead.php`, который принимает `POST` с `payload` от
  `submitLead`, проверяет ловушку и обязательные поля, и создаёт лид в
  Битрикс24 через входящий вебхук (`crm.lead.add`).
- Адрес вебхука хранится **только на сервере**, вне репозитория и вне `dist/`
  (например, в файле конфигурации выше корня сайта или в переменной окружения).
  В коде лендинга — только URL обработчика.
- `submitLead` меняется на `fetch(HANDLER_URL, { method: 'POST', body: JSON })`,
  возвращает `{ ok }` по ответу сервера; при ошибке форма уже показывает
  телефон и сохраняет введённые данные.
- После подключения: убрать предупреждение из README и CLAUDE.md, подставить
  `YM_COUNTER_ID`, проверить цели `calc_submit` / `business_submit`.

Остальные блоки по очереди: шоурум (`#showroom`, на него уже ведёт кнопка
с экрана «Что внутри»), галерея работ.
