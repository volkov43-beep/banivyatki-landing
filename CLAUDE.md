# CLAUDE.md — памятка по проекту «Бани Вятки»

Лендинг компании «Бани Вятки» (Киров): мобильная баня «Подкова» — готовая
конструкция, которую привозят и ставят на участке. Покупатель делегирует:
страница говорит на языке «что вы не будете делать», а не «какая у нас баня».
Каждый блок заканчивается числом или проверяемым фактом.

Репозиторий публичный: https://github.com/volkov43-beep/banivyatki-landing
Сайт: https://banivyatki.ru — хостинг Beget, в корне домена, выкладка по FTP
из GitHub Actions. Старый адрес volkov43-beep.github.io/banivyatki-landing/
отдаёт только страницу-переадресацию.

## Правила безопасности (читать первыми)

- Репозиторий публичный: никаких ключей, вебхуков, токенов и паролей в коде
  и в истории коммитов. Ключи только через переменные окружения (`.env`,
  в `.gitignore`) и секреты GitHub Actions: ключ Яндекс Карт — только через
  секрет `VITE_YMAPS_KEY`, доступ к FTP Beget — только через секреты
  `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`; их значения не печатать ни
  в чат, ни в консоль, ни в логи сборки (GitHub маскирует секреты в журнале,
  но `echo` и отладочный вывод действий всё равно не включать). Проверять
  `git log -p -S` перед пушем.
- Никаких персональных данных клиентов: имён, телефонов, адресов, ссылок на
  их страницы. В данные сайта попадают только населённые пункты
  (`src/data/objects.js`). Отзывы — только с именем как на площадке и датой.
- Никаких себестоимостей, маржи и внутренних прайсов. На сайте только цены
  «от» из `src/data/calculator.js`.
- Реквизиты компании (банковские) на сайте не публикуем без отдельного
  решения. В политике конфиденциальности — ИНН/ОГРН/адрес и почта
  оператора `banivyatki@mail.ru` (единственное место с почтой: в подвале
  и формах её нет). Данные компании на странице: телефон +7 (8332) 77-57-70,
  ИНН 9718285920 (подвал), адрес шоурума Ленина, 71Б и производства
  (Северное Кольцо) — это публичные данные, не секрет.
- Нашёл в коде или истории что-то похожее на ключ, вебхук или личные
  данные — сказать владельцу, что и где, и не удалять молча: переписывать
  историю публичного репозитория — его решение.
- Ссылку вебхука Битрикс24 не запрашивать и не принимать: она живёт только
  на сервере в `private/config.php` (вне папки сайта, владелец кладёт
  руками), в репозитории — только образец `server/config.sample.php`
  с пустыми значениями. Коды полей, стадий и источников — тоже только там.
  Пароли и доступы к хостингу, панели Beget, CRM и кабинету Яндекса в чат
  тоже не запрашивать. `server/config.php` в `.gitignore` на всякий случай.
- Формы отправляют заявки через `public/api/lead.php` (см. «Формы и
  заявки»). Рекламу (Директ) не запускать, пока владелец не проверил на

## Стек и сборка

- Vite 7 + React 19 + Tailwind CSS 3. JavaScript, без TypeScript.
- `npm install`, `npm run dev` (локально), `npm run build` (в `dist/`),
  `npm run preview` (просмотр сборки).
- Две страницы Vite: `index.html` (лендинг) и `privacy/index.html` (`/privacy/`).
  Входы заданы в `vite.config.js`.
- Базовый путь — корень домена: `base: '/'` в `vite.config.js`, флаг
  `--base` в сборке не передаётся. Пути к файлам из `public/` в коде —
  по-прежнему через `import.meta.env.BASE_URL`, в HTML — через `%BASE_URL%`
  (руками `/photos/…` не писать: если сайт когда-нибудь снова окажется
  в подпапке, достаточно поменять `base`).
- `public/.htaccess` попадает в корень `dist/` при каждой сборке: переадресация
  `www.banivyatki.ru` → `banivyatki.ru` (301), gzip для html/css/js/svg/json,
  `Options -Indexes`, кэш по таблице ниже. Переадресацию HTTP → HTTPS не
  прописывать: она включена на стороне хостинга, два правила конфликтуют.
  Проверять на настоящем Apache (в песочнице ставится `apt-get install
  apache2`, конфиг с `AllowOverride All` на `dist/`, модули rewrite,
  headers, expires, deflate), а не на глаз.

  | Что | `Cache-Control` | Почему |
  | --- | --- | --- |
  | `/assets/*` (css, js с хешем в имени) | `public, max-age=31536000, immutable` — год | при изменении меняется имя файла; правило в `<If "%{REQUEST_URI} =~ m#^/assets/#">`, оно применяется после `<FilesMatch>` |
  | шрифты (woff2, woff, ttf, otf) | год | на странице их нет (Google Fonts), правило на будущее |
  | картинки вне `/assets/` (webp, png, jpg, svg, ico: фото, favicon, og) | `public, max-age=604800` — 7 дней | имена постоянные, кадры заменяются под тем же именем |
  | html | `no-cache` | всегда перепроверяется |

  `mod_expires` дублирует те же сроки в `Expires`. Строгого года для фото
  **не ставить**: вернувшийся посетитель месяцами видел бы старый кадр.
- SEO-теги в `<head>` главной: `canonical` `https://banivyatki.ru/`,
  `description` (160 символов, собран из фраз первого экрана и подвала,
  цены нет — она считается из `MIN_PRICE`, а в HTML попала бы руками),
  `og:type` website, `og:url`, `og:title` (= `<title>`), `og:description`
  (= `description`), `og:image` `https://banivyatki.ru/og-banivyatki.jpg`
  с `og:image:width/height` 1200 × 630, `og:locale` ru_RU, `og:site_name`
  «Бани Вятки», `twitter:card` summary_large_image. Менять текст описания
  или заголовка — в обоих местах (`description` и `og:description`).
  `public/og-banivyatki.jpg` — кадр первого экрана `hero-autumn-1920`
  (окно 1600 × 840 от левого края, верх 60, → 1200 × 630, JPEG 82,
  mozjpeg, ~94 КБ, без EXIF), без текста поверх, не отзеркален (на сайте
  зеркало через CSS). `public/robots.txt`: `User-agent: *`,
  `Disallow: /privacy/`, `Host: https://banivyatki.ru` (Яндекс директиву
  `Host` с 2018 года не читает, главное зеркало — 301 и Вебмастер;
  оставлена по заданию). Карты сайта нет сознательно: одна страница.
- Переменные окружения: `VITE_YMAPS_KEY` — ключ Яндекс Карт (см. `.env.example`).

### Деплой на Beget (banivyatki.ru)

Workflow `.github/workflows/deploy-beget.yml`: при пуше в `main` (или вручную
через «Run workflow») собирает сайт (`npm run build`, ключ карт из секрета
`VITE_YMAPS_KEY`), проверяет, что в `dist/` есть `index.html`,
`privacy/index.html` и `.htaccess` и нет строки `banivyatki-landing`, и
выкладывает `dist/` по FTPS (`protocol: ftps` — FTP поверх TLS, порт 21)
действием `SamKirkland/FTP-Deploy-Action` (секреты `FTP_SERVER`,
`FTP_USERNAME`, `FTP_PASSWORD`). FTP-аккаунт привязан
к папке сайта, поэтому `server-dir: ./` — корень `public_html`, путей
вроде `/<домен>/public_html` в настройках нет. Полная очистка папки
(`dangerous-clean-slate`) выключена: действие ведёт файл состояния
`.ftp-deploy-sync-state.json` в корне сайта и удаляет только то, что само
выложило раньше (старые хэшированные бандлы); файлы, которых в сборке
никогда не было (PHP-обработчик заявок), не трогает. `log-level: minimal`.
Первая выкладка (run 1, 5 октября 2026) прошла по обычному FTP; затем
переключено на FTPS. Если выкладка по FTPS падает — не подбирать настройки
вслепую: откатить `protocol: ftps` и показать владельцу ошибку сервера.

Выкладка идёт **автоматически после каждого мержа в `main`** — вливать PR
значит публиковать.

### Старый адрес на GitHub Pages

`.github/workflows/pages-redirect.yml` публикует на GitHub Pages одну
страницу `pages-redirect/index.html`: `<meta http-equiv="refresh">` и
`location.replace` на `https://banivyatki.ru/`, `canonical` на новый адрес,
`<meta name="robots" content="noindex">`, без счётчика Метрики. Запускается
при изменении этой страницы или самого workflow в `main` и вручную.
В Settings → Pages источник остаётся «GitHub Actions». Прежний workflow
`deploy-pages.yml` удалён. Вложенные старые адреса (например
`…/banivyatki-landing/privacy/`) на Pages отдают 404 — одна страница по
заданию, `404.html` не добавлялась.

Рабочий процесс: каждое задание — в ветке от свежего `main`, коммиты, push,
pull request; вливает владелец (или по его прямой просьбе в чате). После
мержа ветку пересоздавать от `main`, а не стекать поверх влитой истории.
Если задача зависит от не влитого PR — сказать об этом первой строкой
ответа. Влитый PR не дополняется: правки после мержа — новым PR. Фото
владелец присылает не больше 5 за сообщение: запрашивать партиями по
именам и не открывать PR, пока не пришли все. Ветка задания одна на чат
(`claude/<имя>`); после мержа старые ветки `claude/*` на GitHub можно
удалять — всё их содержимое в `main`.

Как устроено общение с владельцем (проверено на практике):
- Код не трогать, пока не пришло задание; каждое задание касается только
  названного блока. Сначала разбор и вопросы, если они есть, потом код.
- Файлы пришли без имён — не угадывать: предложить соответствие по
  содержимому (что на кадре → какое имя) и попросить подтвердить. Владелец
  подтверждает одной фразой («соответствие верное») — тогда конвертировать.
- В каждом отчёте: скриншоты 1440 и 390 (при изменении раскладки — ещё
  1024 и 768), список отклонений от задания с причиной и отдельно — что
  проверить не удалось (нет сети: Google Fonts, Яндекс Карты, Метрика).
- Отзывы, подписи объектов, тексты FAQ — буквально из задания; менять
  текст можно только с пометкой «отклонение» в отчёте.
- Коммиты: заголовок по-русски, что сделано; подпись среды Claude Code
  (`Co-Authored-By`, `Claude-Session`) в конце. Описание PR — что сделано,
  что проверено, что не проверено, ссылка на сессию. Имя модели в код,
  комментарии и заголовки PR не писать. Шаблона PR в репозитории нет.

## Файлы данных (`src/data/`)

Тексты и цифры блоков живут в данных, компоненты их только показывают.
Менять текст — в `data/`, не в JSX (исключения: темы «Что внутри» и шаги
«Как проходит заказ» — тексты в самих компонентах).

| Файл | Экспорты | Структура записи |
| --- | --- | --- |
| `calculator.js` | `SEASONS`, `LAYOUTS`, `CARDS`, `MIN_PRICE`, `WARM_NOTES`, `QUOTE`, `BUSINESS`, `PHONE`, `formatPrice` | `CARDS[season]` — массив `{ id, title, size, layout, photo, price, inside, delivery }`; `photo` — строка пути `photos/size-3m.webp` (летние, один файл) или `{ name, alt }` (зимние, две ширины). `MIN_PRICE` считается, руками не писать |
| `works.js` | `WORKS_TITLE`, `WORKS_SUBTITLE`, `EQUIPMENT_VISIBLE`, `WORKS_NOTE`, `formatWorkPrice`, `WORKS` | `{ id, name, caption, equipment[], price, photos: [{ name, alt }] × 2, calc: { season, cardId } \| null }` |
| `reviews.js` | `SOURCES`, `REVIEWS_TITLE`, `REVIEWS_SUBTITLE`, `VISIBLE`, `REVIEWS`, `BUSINESS_REVIEW` | `{ id, label, author, status \| null, source: 'avito' \| 'yandex', rating, date (ISO), dateText, text, photos: [{ name, alt, width, height }] }`; `SOURCES[id]` — `{ id, name, rating, count, icon, ratingIcon }` |
| `objects.js` | `OBJECTS`, `PLACES_LINE`, `KIROV_LABEL`, `OBLAST_BOUNDS` | `{ name, region, lat, lon, group: 'kirov' \| 'oblast' \| 'far' }`; порядок `far` = порядок строки «А ещё» |
| `visit.js` | `VISIT_TITLE`, `VISIT_SUBTITLE`, `SHOWROOM`, `PRODUCTION`, `VIDEO`, `VISIT_TYPES`, `VISIT_FORM` | карточка `{ id, photo: { name, alt }, title, address?, text, button, galleryTitle?, numbered?, gallery?: [{ name, caption, alt, wide? }] }`; `VISIT_TYPES` — `[{ id: 'showroom' \| 'production' \| 'video', label }]` |
| `faq.js` | `FAQ`, `plainAnswer` | `{ n, group, q, text, list?, after? }`; ссылки в `text` — `[текст](#id)`, абзацы через пустую строку |
| `benefits.js` | `BENEFITS_TITLE`, `BENEFITS_SUBTITLE`, `BENEFITS_BUTTON`, `BENEFITS` | `{ id, icon, title, text }`, иконка по `icon` в `benefits/BenefitIcons.jsx` |

Общие правила:
- `id` — латиница с дефисами, стабильный: по нему ходят цели Метрики
  и события (`requestCalc(season, cardId)`), менять — значит проверить
  `works.js` (`calc.cardId`) и таблицу целей.
- Даты — ISO в `date` и готовая строка в `dateText` (склонения не
  вычисляются).
- Цены — числа в рублях, форматирование в `formatPrice` / `formatWorkPrice`
  (неразрывные пробелы, ₽).
- Имена файлов фото — без расширения и ширины (`name`), путь собирает
  компонент.

`podkova` и `alert-on-dark` — пара «наше / чужое», применяется в блоке
сравнения: Подкова — `podkova` и арка, бочка — `alert-on-dark` и круг
(зоны в карточках, подписи под чертежом обвязки). `forest` для меток
не годится: на тёмном фоне он не читается.

Два зелёных для текста — по фону, не взаимозаменяемы: `podkova` — только
на тёмном (`ink` / `forest`), на бежевом контраст 1,9 — не проходит;
`price` — только на светлом (`surface` / `surface-2`), это цена объекта
в карточках «Наших работ». Цены калькулятора остаются `accent`.

На тёмном фоне использовать только `*-on-dark`. Не использовать: зелёный
как доминанту, терракоту около #D97757, градиентные заливки, тени под карточками.

Правила для `forest`:
- Только **фон** тёмных карточек и блоков. Не для текста и не для заголовков
  на бежевом: там он почти не отличается от чёрного. Исключение по
  заданию — пометка на фото слива в «Что внутри»: рамка и выноска `forest`
  2 px и плашка `forest` с текстом `surface` (на светлом дереве accent
  сливается с досками).
- На `forest` те же цвета текста, что на `ink`: светлый — `surface`,
  второстепенный — `muted-on-dark`, акцент и кнопки — `accent`. Контраст
  проверен: 13,8 / 6,3 / 5,6.
- Блоки на `forest`: «Что вы получаете», «Как проходит заказ», финальная
  форма; карточки на `forest`: форма записи на показ (`showroom/VisitForm`).
  Карточка вопроса FAQ — на `surface`, не на `forest`. Подвал — на `ink`,
  чтобы отделяться от зелёной формы. Hero, сравнение и карта — на `ink`.
- Поля на `forest`: прозрачный фон, рамка `rgba(244,234,223,0.28)`, текст
  `surface`, плейсхолдер `muted-on-dark`; `Segmented` со `scheme="dark"`.

### Кнопки

Все кнопки страницы — через `components/Button.jsx`. Три типа (`variant`):

| Тип | Вид | Где |
| --- | --- | --- |
| `primary` | заливка `accent`, текст `ink`, скругление 4 px | одна на блок: отправка формы, переход в калькулятор, запись на показ |
| `secondary` | прозрачный фон, рамка 1,5 px; текст `accent` на светлом (`scheme="light"`), `surface` на тёмном и зелёном (`scheme="dark"`) | второе действие рядом с главной («Показать ещё 4 отзыва»), кнопка в карточке объекта «Рассчитать такую» (`md`, ширина по содержимому, по левому краю) |
| `link` | текст `accent`, подчёркивание полупрозрачное `rgba(201,138,46,0.4)` | мелкие действия внутри карточек: «+ ещё N» / «Свернуть» в комплектации, «Читать полностью», «изменить», места в строке «А ещё» |

Состояния: наведение — `primary` фон `accent-hover` и мягкая тень
`0 4px 14px rgba(26,21,18,0.22)`, `secondary` заливается (`accent` на светлом,
`surface` на тёмном, текст `ink`), `link` — подчёркивание непрозрачное;
нажатие — `accent-active` / `surface-2`, без сдвига; фокус с клавиатуры —
рамка 2 px `accent` с отступом 3 px (общее `:focus-visible` в `index.css`).
Переходы 150 мс только по цвету и тени, ничего не двигается и не растёт.

Стрелка (`arrow`): у главных кнопок, ведущих к другому блоку (калькулятор,
форма записи, блок показа), в конце текста тонкий шеврон, нарисованный в коде
по правилам иконок: линия 1,5 px, скруглённые концы, цвет от текста кнопки
(`currentColor`), 20 × 20. При наведении сдвигается вправо на 3 px за 150 мс
(`group-hover`), при `prefers-reduced-motion` не двигается. У кнопок отправки
форм («Получить расчёт», «Задать вопрос», «Записаться») и у полоски на
телефоне стрелки нет.

«Дыхание» — только у одной кнопки на странице, «Рассчитать стоимость» на
первом экране (`SectionHero`): когда кнопка впервые попадает в поле зрения
(IntersectionObserver), один цикл 1,2 с — тень `accent` нарастает и уходит
(`@keyframes bv-breathe` в `index.css`, класс `.bv-breathe`), размер и
положение не меняются. Повторно не запускается; если до появления навели
мышь, нажали или дали фокус — не запускается вовсе; при
`prefers-reduced-motion` не выполняется (проверка и в JS, и в CSS). Других
анимаций появления на странице нет.

Кнопка внизу блока («Собрать свою баню», «Узнать цену Подковы», «Посмотреть
баню вживую», «Рассчитать стоимость» в «Как проходит заказ») — по центру,
подводка над ней тоже по центру. Кнопки в карточках и формах — как в них
принято.

Размеры (`size`): `lg` — крупная, формы и кнопки блоков: min-height 56 px,
текст 17 px, `px-8`; `md` — обычная, внутри карточек и полоска на телефоне:
44 px, 15 px. У `link` размер задаёт кегль: `lg` 17 px жирный, `md` 15 px
жирный, `sm` 14 px обычный. `as="a"` для ссылок, `full` — на всю ширину,
`fullMobile` — на всю ширину до 1023 px. Тексты кнопок и высоту одного
размера не разводить между блоками. Не через `Button`: переключатели
`Segmented` (радиогруппы), карточки калькулятора (радио с подписью
«Выбрать»), «×» и стрелки увеличения фото, аккордеон FAQ, телефон в шапке.

### Иконки

Смысловые иконки на странице только в блоке «Что вы получаете»
(`benefits/BenefitIcons.jsx`) и пара «бочка / Подкова» в блоке сравнения
(`comparison/BathMarks.jsx`: круг и арка, 18 / 14 px, цвета
`alert-on-dark` / `podkova` вместо `accent`, толщина 1,5 px на любом размере
через `non-scaling-stroke`). Иконки рисуются в коде инлайновым SVG, готовые наборы
и внешние библиотеки не используются. Только линии без заливок и градиентов,
толщина 1,5 px, скруглённые концы и стыки, цвет `accent` через
`currentColor`, 40 × 40 в viewBox `0 0 40 40`, одинаковая оптическая
плотность у всех, простая узнаваемая геометрия, без теней и текста внутри,
`aria-hidden="true"` (смысл несёт заголовок плитки).

Исключение — звёзды рейтинга (`RatingStars`): в карточках отзывов и в
плашках они **залитые** цветом `accent`, без контура. Пустые контурные
звёзды читаются как «оценка не выставлена», поэтому здесь заливка нужна.
Единственное место с контурными звёздами — плашка Авито на первом экране
(`outline`: контур 1,5 px, заполненная доля залита).

Служебные значки (не иконки блоков, под правило 40 × 40 не подпадают, но
их список держим здесь, чтобы не появлялись новые без решения):
- шеврон в кнопках `arrow` (`Button.jsx`): 20 × 20, линия 1,5 px,
  `currentColor`;
- трубка в плашке телефона в шапке (`Header.jsx`): 16 px, **залитая**
  `currentColor` — единственная залитая пиктограмма, принято;
- галочка «Выбрано» на карточке калькулятора (`CalculatorCard.jsx`):
  16 × 16, линия 2,5 px — толще остальных, чтобы читалась на accent;
- стрелки увеличения фото объектов (`works/Lightbox.jsx`): 20 × 20,
  линия 2 px; стрелки просмотра фото отзывов (`reviews/PhotoViewer.jsx`):
  20 × 20, линия 1,5 px — толщины разные, долг на выравнивание;
- «×» закрытия окон и «+» аккордеона FAQ — текстом / CSS, не SVG;
- иконки площадок отзывов — официальные файлы WebP (`SourceIcon`), не
  рисуются.

### Разделители разделов внутри блока

Используются в «Что внутри» (`SectionDivider` в `SectionInside.jsx`): по
центру капсула-пилюля (рамка 1,5 px `accent`, отступы 7 × 18 px, текст
`accent` Onest 700 13 px капсом, разрядка 0,08em), слева и справа тонкие
линии 1 px `muted` до краёв (`h-px flex-1`, минимум 8 px). Текст в одну
строку: до 479 px — 12 px и 0,06em, до 379 px — 11 px, до 359 px — 10 px
(иначе самая длинная надпись не помещается). Отступ над разделителем
больше, чем между темами (112/160 против 80/112), у первой темы после
разделителя нет верхней линии. Все разделители в блоке одинаковые.

### Пометки поверх фото

Когда на снимке нужно показать деталь (`AnnotatedPhoto.jsx`): фото и
пометка — **один SVG с общим viewBox в размер файла** (1280 × 960),
внутри `<image>`, поверх рамка/выноска и плашка; координаты измерять по
пикселям файла. Сам снимок не трогаем: ни подсветки, ни ретуши, ни
обводки букв. Рамка и выноска — `forest` 2 px (`non-scaling-stroke`);
подпись — плашка `PhotoTag`: фон `forest`, скругление 4 px, отступы
4 × 10 px, текст `surface` Onest 700 14 px (контраст 13,8:1). Плашка
в свободном месте кадра, не перекрывает деталь; на узком фото держит
14 px, пока рост в единицах viewBox не больше 1,8 раза, дальше
уменьшается вместе с картинкой (не переезжает). У SVG `<image>` нет
`srcset`: файл 640/1280 выбирается в JS по ширине × плотности,
подставляется лениво. `accent` на светлом дереве не читается — не
использовать.

### Сетка и брейкпоинт

- Контейнер `max-w-container` (1200 px), отступы `px-gutter` 24 / `md:px-gutter-lg` 48.
- Секции `py-section-y` 64 / `md:py-section-y-lg` 96.
- Брейкпоинт раскладки — **1024 px** (`lg:`): до 1023 мобильная раскладка,
  от 1024 компьютерная. Внутри блоков есть свой порог **600 px**
  (`min-[600px]:`): ниже него пары фото ставятся друг под другом, подписи
  на чертежах заменяются номерами, главная схема разбивается на две.

### Схемы и чертежи

- Микро-схемы — инлайновый SVG в чертёжной манере: контуры без заливки,
  размерные и выносные линии `accent`, подписи через `diagrams/Diagram.jsx`
  (схемы `dark` / `light`, режим `scale`, при котором подписи держат заданный
  размер в px на любом масштабе через CSS-переменную `--s`).
- Готовые чертежи (WebP с прозрачностью) ставятся через **один SVG с общим
  viewBox в размер картинки**: внутри `<image>`, поверх текст и выноски,
  поэтому подписи масштабируются вместе с рисунком. Опорные точки измеряются
  по пикселям файла (альфа-канал, цвет), не на глаз. Текст 14 px через `--s`,
  выноски 1.5 px `accent` с точкой; размерные линии 1 px со стрелками,
  выносные тоньше и полупрозрачные.
- **До 600 px**: у чертежей карточек (`LabeledDrawing`) вместо текста золотые
  номера в кружках и список под картинкой; главная схема сравнения
  (`CrossSectionDiagram`) показывается двумя SVG друг под другом с окнами
  viewBox одинаковой ширины (820), чтобы люди остались одного роста.
- Картинка внутри SVG грузится лениво: `href` ставится по IntersectionObserver
  (у SVG `<image>` нет `loading="lazy"`). У SVG `role="img"` и `aria-label`.

## Порядок блоков на странице

Статус: **готов** / **в работе** / **ждёт данных**. Отправка всех форм —
заглушка (console.log) до подключения Битрикс24, это не статус блока.

1. `Header` — **готов**. Логотип 64/48 px со ссылкой на начало, телефон
   (на телефоне плашка). Клик по телефону — цель `phone_click`.
2. `SectionHero` (`#top`) — **готов** (переделка по разбору с директологом:
   текст слева и плашка рейтинга сделаны; формы в модальном окне и квиз —
   см. «Что не доделано»). Сразу за ним «Наши работы»: стык фото на `ink` с
   карточками на `surface-2`. Картинка `<picture>` (мобильный файл до 1023,
   горизонтальный от 1024) **отзеркалена по горизонтали через CSS**
   (`-scale-x-100`, файлы и предзагрузка не менялись): в исходнике баня и
   женщина слева, теперь справа и смотрят к тексту. Колонка текста слева
   (до 42 % ширины, `pl-gutter-lg`, начинается под логотипом шапки, `pt-20`,
   центр по высоте через `my-auto`), затемнение слева направо и ореол за
   колонкой зеркально прежним; контраст по пикселям на 1440 / 1024: заголовок
   ≥ 7:1, цена `accent` ≥ 5,6:1, факты ≥ 11:1. Порядок: заголовок

## Решения по тексту

- «Подкова» всегда с большой буквы, когда это название продукта
  («Баня-Подкова», «У Подковы пол прямой»). Строчная — только для формы
  («формы подкова»). В подписях главной схемы — «Баня-бочка» и «Баня-Подкова».
- Наценку за безнал и за оплату картой на сайте не упоминаем.
- Телефон в формах не заменяет заявку: везде ведём на форму (калькулятор,
  форма вопроса в FAQ), чтобы отслеживать конверсию. Под FAQ телефона нет.
- В карточках только «от», без диапазонов «от–до». Минимальная цена
  калькулятора = цена на первом экране: **293 000 ₽**, первый экран берёт
  `MIN_PRICE` из `src/data/calculator.js`, руками не писать.
- В готовых банях 4–6 м (тёплый сезон) не упоминать двойной проливной пол
  и вентиляцию «живая баня» — их там нет.
- Не упоминать басту, окна 300×300, мощность подключения (киловатты и сечения).
- Сумму задатка в блоке «Как проходит заказ» не пишем; в FAQ — «от 5 000 ₽»
  (подтверждено). Про очередь и сезонность не пишем.
- Пол Подковы 2000 мм, наружная ширина 2400, высота 2300 — цифры публичные.
- Канон цифр: бани с 2012 года, Подкова с 2019-го, больше 1000 бань, из них
  больше 300 Подков; гарантия 5 лет, продлевается ежегодным обслуживанием.
- Без анимаций появления по скроллу, таймеров, всплывающих окон, бейджей
  «Акция»/«Хит», карусели в отзывах. Без иконок в карточках калькулятора;
  исключения — плитки «Что вы получаете» и пара «бочка / Подкова» в блоке
  сравнения, там иконки по правилам раздела «Иконки». Одна кнопка на первом экране.
- Ссылок на avito.ru и yandex.ru на странице нет: площадки показаны иконками
  и текстом. Отзывы — настоящие, тексты не переписывать (только сокращать
  через «…» и править явные опечатки).

### Обработчик на сервере (Beget, PHP 8.3, без Composer)

Структура на сервере от папки сайта: `public_html/api/lead.php` (из сборки),
`private/config.php` (секреты, владелец кладёт руками), `private/lib.php`
и `private/retry.php` (из `server/`, копируются руками), `private/queue/`,
`private/queue/failed/`, `private/log/`, `private/ratelimit/` (создаются
сами, нужна запись для PHP). Путь до `private/` обработчик считает от
своего файла: `dirname(__DIR__, 2) . '/private'`. Нет `lib.php` или
`config.php` — ответ `500 {"ok":false,"error":"server_config"}` без путей,
запись в `error_log`; синтаксическая ошибка в конфиге — `server_error`,
белого экрана нет (`display_errors=0`, `set_exception_handler`,
`register_shutdown_function`).

`lead.php`, проверки по порядку: не POST → 405; `Origin` есть и не
`https://banivyatki.ru` / `https://www.banivyatki.ru` → 403; тело не JSON
или больше 64 КБ → 400 `bad_json`; ловушка `website` заполнена или
`elapsed_ms` < 3000 (или нет) → `{"ok":true}`, в Битрикс ничего, в журнале
`dropped`; больше 5 заявок с одного IP за 10 минут → 429 (файловый счётчик
`private/ratelimit/<sha1 ip>.json`, IP из `REMOTE_ADDR` или заголовка
`client_ip_header` из конфига); нет `form`/`phone` или форма неизвестна →
400 `bad_request`; телефон не приводится → 400 `bad_phone`. Телефон: только
цифры, 11 с 7/8 в начале → `+7` и десять последних, 10 → `+7` и они,
остальное отказ (тесты `server/tests/phone.test.php`, 22 случая).

Битрикс (cURL, соединение 5 с, весь запрос 10 с, вебхук из конфига):
`crm.duplicate.findbycomm` (PHONE, CONTACT) → найден — берём первый, иначе
`crm.contact.add` (NAME или «Клиент с сайта», PHONE WORK, ASSIGNED_BY_ID,
OPENED Y, UTM по карте `contact_utm_fields`) → `crm.deal.add` (TITLE,
CATEGORY_ID, STAGE_ID, ASSIGNED_BY_ID, CONTACT_ID, SOURCE_ID — код Директа
при `utm_source=yandex` + `utm_medium=cpc`, иначе код сайта,
SOURCE_DESCRIPTION — тип формы словами, поле типа связи из конфига,
COMMENTS, UTM по карте `deal_utm_fields`). `OPPORTUNITY` не заполняем.
Названия: `Сайт · Расчёт · 4–4,5 м, тёплый сезон · от 330 000 ₽`
(без варианта/цены части опускаются), `Сайт · Запись: шоурум`,
`Сайт · Вопрос`, `Сайт · Расчёт` (final), `Сайт · Для бизнеса` (business —
в задании формы не было, принято по аналогии; SOURCE_DESCRIPTION
«Калькулятор, для бизнеса», компания и комментарий — в COMMENTS).
Комментарий — строки «Форма / Выбранный вариант / Показанная цена / Способ
связи / Тип визита / Вопрос / Компания / Комментарий / Страница /
Переход с / Время отправки (МСК) / Метки», пустые пропускаются; при
найденном контакте первой строкой «Повторное обращение: <portal_url>/crm/
contact/details/<id>/». Ответ Битрикса наружу не уходит никогда.

Битрикс недоступен или вернул ошибку → сайту всё равно `{"ok":true}`,
заявка файлом в `private/queue/` (`attempts`, `last_error`, `lead` с уже
созданным `contact_id`, чтобы повтор не создал второй контакт). Если и
очередь не записалась — `500 server_error` (человек увидит телефон).
`retry.php` (только CLI: по HTTP сразу 404 без вывода; блокировка
`private/retry.lock`): берёт очередь по порядку, до 10 попыток, потом
`queue/failed/` и запись в журнал; заодно удаляет журналы старше 30 дней
и устаревшие счётчики частоты. Журнал `private/log/ГГГГ-ММ-ДД.log`: время,
`form`, `result` (sent / queued / retry_later / failed / dropped /
rejected / error), код ошибки, `deal`, `contact=<id>:new|found`,
`attempts`, короткий хеш телефона (`phone=`, первые 10 знаков sha256);
телефона, имени и текста вопроса в журнале нет.

Проверка без сети: `php server/tests/handler.test.php` поднимает
`php -S` для сайта, для `private/` и для заглушки Битрикса
(`server/tests/bitrix-stub.php`, режимы ok / found / error / timeout) и
прогоняет 38 случаев, включая таймаут 10 с, очередь, retry, лимит частоты,
отсутствие и поломку конфига. Браузерная проверка форм — Playwright с
`page.route('**/api/lead.php')`. Живой Битрикс и живые заголовки
проверяет владелец.
- UTM (`src/lib/utm.js`): при первом заходе сохраняются в `sessionStorage`
  (`bv_utm`), при отправке берутся оттуда.
- Защита от спама в `LeadForm`, `FaqQuestionForm`, `VisitForm` и `FinalForm`: скрытое поле-ловушка
  (honeypot `website`) и проверка, что форму заполняли дольше 3 секунд. Без
  капчи. Ловушка сработала — показываем «принято», ничего не отправляем.
- Согласие на обработку данных — чекбокс со ссылкой на `/privacy/`, обязателен.
- Обещание по московскому времени (`src/lib/callback.js`) — общая функция:
  `callbackWhen()` → «в течение 15 минут» / «завтра с 9:00» / «в понедельник
  с 9:00» (подзаголовок формы FAQ), `callbackPromise()` → «Перезвоним …»
  (формы заявки). Правило: Пн–Пт 9:00–17:44 → 15 минут; Пн–Чт с 17:45 и
  Вт–Пт до 8:59 → завтра с 9:00; Пт с 17:45, Сб, Вс, Пн до 8:59 →
  в понедельник с 9:00. Проверка: `?now=2026-09-26T20:00` (московское время).
- После отправки форма скрывается, показывается подтверждение с обещанием;
  при ошибке — сообщение с телефоном, введённый текст остаётся. Без
  всплывающих окон.
- Телефон компании: +7 (8332) 77-57-70, `PHONE` в `src/data/calculator.js`.
  Маска и нормализация — `src/lib/phone.js`.

## Обработка картинок

Главное (для любого нового фото):
- WebP, качество 80; при перевесе 75, ниже не опускать; если и на 75 не
  влезает — лёгкое шумоподавление (`blur(0.6)`), не помогло — сказать

- Две ширины `<имя>-1280.webp` и `<имя>-640.webp`, подключение через

  80 КБ. Пропорции 4:3 (горизонтальные) или 3:4 (вертикальные), обрезка

  `sharp(buf).toFile()` — иначе файл пережимается второй раз.

  ширины удаляются автоматически, иначе удалить неиспользуемые.

  доходит до вернувшихся посетителей не позже чем через неделю. Новый
  кадр под новым именем (номер или суффикс) по-прежнему чище, но теперь

- Playwright: без `page.setDefaultTimeout(5000)` каждый неудачный шаг ждёт
  30 с и команда упирается в лимит времени.
- Клик по ссылке `tel:` в шапке ломает все последующие действия на
  странице (навигация на `tel:`) — проверять его последним.
- Чекбокс согласия: `check()` падает с «did not change its state» —
  `check({ force: true })`.
- `<noscript><div>…</div></noscript>` в `<head>` — Vite ругается
  «disallowed-content-in-noscript-in-head» и ломает разбор; поэтому
  noscript Метрики стоит первым в `<body>`.
- `align-items: safe center` (`lg:items-[safe_center]`) Chromium не
  применяет — центрирование через `my-auto` + `pt-*`.
- В строках исходников есть неразрывные пробелы (U+00A0): поиск и
  замена по точной строке молча не находят — искать регуляркой или
  копировать строку из файла, не набирать руками.
- `vite build --mode development` **не** включает `import.meta.env.DEV`:
  поведение «только в консоль» проверять на `npm run dev` (порт 5173).
- Проверка EXIF скриптом sharp по всей папке падает на одном файле
  «unsupported image format» — проверять новые файлы по одному при
  конвертации, не полагаться на общий прогон.
- После `page.reload()` эмуляция `pointer: coarse` теряется (см. выше).
- Правки `CLAUDE.md` и длинных текстов — скриптом с точными заменами
  (Python `str.replace` с проверкой, что вхождение одно), не `sed` по
  кириллице с кавычками «».
